##### Description

<!-- describe what is the question, suggestion or issue and why this is a problem for you. -->

The Kotlin code generator is not sanitizing enum values correctly. This occurs for hyphenated values where it gets translated to `Minus`. 

This was previously addressed in Issue #9683 and partially fixed in PR #16267 (since it does not cover enum values). The fix should be quick to address but let me know if you need me to submit a PR for this

##### openapi-generator version

<!-- which version of openapi-generator are you using, is it a regression? -->

Version 7.13.0

##### OpenAPI declaration file content or url

Any OpenAPI file that contains an enum whose value contains an hyphen:
```yaml
properties:
  propertyName:
    type: string
    default: HYPHENATED-VALUE
    enum:
      - HYPHENATED-VALUE
```

##### Steps to reproduce

<!-- unambiguous set of steps to reproduce the bug.-->

1. Go to [AbstractKotlinCodegenTest.java](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/test/java/org/openapitools/codegen/kotlin/AbstractKotlinCodegenTest.java#L46-L97)
2. Add an assertion for any enum type. Example: `assertEquals(codegen.toEnumVarName("long-Name", null), "longName");`
3. Run the test
4. Verify that it fails. It should be `longName` instead of `longMinusName`

##### Suggest a fix

<!-- if you can't fix the bug yourself, perhaps you can point to what might be
  causing the problem (line of code or commit), or simply make a suggestion -->

Replace line `modified = value;` with `modified = sanitizeName(value, "\\W-[\\$]");` in [AbstractKotlinCodegen.java](https://github.com/OpenAPITools/openapi-generator/blob/d04c0ddbb4b7037adfffe5996807f6bbd209fbf6/modules/openapi-generator/src/main/java/org/openapitools/codegen/languages/AbstractKotlinCodegen.java#L575)
Add unit tests for the different enum properties. Example:
1. original -> `long-Name` becomes `longMinusName`
2. snake_case -> `long-Name` becomes `long_name`
3. camelCase -> `long-Name` becomes `longName`
4. PascalCase -> `long-Name` becomes `LongName`
5. UPPERCASE -> `long-Name` becomes `LONG_NAME`
